# 朝の検収

夜間ループ（`scripts/night.sh`）の結果を、実装した本人ではない目で確かめてから `main` に入れる。完了の判定は `pnpm check` が済ませているので、ここでは試験が証明しない所を見る。

## 手順
1. `.night/<日付>/report.md` を読む（日付は省略時に最新）。`[x]` 完了、`[!]` 失敗、停止理由を確かめる。
2. 失敗分（`[!]`）は理由だけを一覧にする。`night-failed/<日付>-<ID>` に残っている。原因が規則や指示の不備なら、`tasks/lessons.md` に 1 行足す案を出す。
3. 完了分ごとに `night-reviewer` エージェントを呼ぶ。渡すのは、ブランチ名（`night/<日付>`）、基点（report の差分の起点、`git merge-base main night/<日付>`）、タスク行。完了タスクが複数あれば並列に呼ぶ。
4. 報告を受け取ったら、規則違反と「未達」の指摘は、差分を自分で開いて確かめる。確かめられなかった指摘は採らない。
5. 人が見る所は、鹿内さんが実際に操作できる形にする（`pnpm dev` の URL、押すボタン、期待する表示）。
6. 最後に次の形でまとめる:
   - タスクごとの判定（マージしてよい／直してからマージ／捨てる）と根拠
   - 鹿内さんが見る所の一覧
   - マージの手順（`git merge --ff-only night/<日付>` が通るか）

## してはいけないこと
- 鹿内さんの確認の前に `main` へマージしない。push しない。
- 失敗分を勝手に直してマージしない。直すなら別の作業として提案する。
- 評価の実行、事前登録の記入、録音の処理はしない（夜間と同じ範囲の外）。
