# 請求の明細の検証 — 作り直し案（2026-11-04、Fable で検討、#32）

状態: 採用（2026-11-04 夜、鹿内さんが承認）。

## いたちごっこの原因
今の `verify.ts` は「モデルが書いた数字が、モデルが写した引用のどこかで正当化できるか」を正規表現で探している。日本語の言い回しの数だけ抜け道がある開いた問題で、探し方が甘いと通ってしまう。Codex の 18 件はすべてこの構造から出た。

## 推奨: 数はコードが拾い、モデルは対応づけだけ

```
文字起こし（発話ごと #0,#1,…）
 ├ (a) candidates.ts  コードが「言われた数」を全部列挙する（ID 付き）
 │      q1 [#0] 4本 / p1 [#2] 1本330円 / t1 [#5] 合計8800円 / a1 2200円 / u1 「二二十円」(円があるのに読めない) / i1 脱着（料金表の語）
 ├ (b) extract.ts     Opus は行ごとに候補 ID を指し、行の status（done／negated／corrected／unsure）と否定・取り消し・断りの文を返す（ID は zod enum をリクエストごとに作る。数字は書かせない）
 ├ (c) resolve.ts     コードが参照を値に戻す。使われない数・二重に使われた数・否定・言い直し・幅 20 秒を検査。モデルの判定と食い違えば聞き返す
 ├ (d) price.ts       料金表で照らす（今の規則を維持）＋金額の検算＋言った合計との照合
 └ (e) 確認事項 → モニター・音声 → 父の答え（同じ候補の文法で読む）→ 承認 → 事務所 PC
```

- 候補の文法の正規化は NFKC・漢数字→算用数字・空白除去だけ。小数点と句読点は消さない。読めない円は必ず確認事項（甘くても安全側に落ちる）。
- 数は「最大の数字の並び」（算用数字・漢数字・十百千万・数字に挟まれた「,」「.」）を 1 つの塊として読み、塊全体が 1 つの数として読めたときだけ数にする（「1万2000」→ 12000）。読めない塊は数にせず、円が続けば読めない円、そうでなければ読めない数（unparsedNumber）。塊の途中や末尾だけを拾わない。単位の付かない数も候補（bareNumber）にする。
- 小数点の片側が欠けた塊（直前が「.」の「.4本」、直後が「.」で次が数字でない「4.本」）も読めない数・読めない円にする（「4」「0.4」と推測しない）。

## 否定・取り消しは誰が守るか（2026-11-04 夜、Codex の 2 回目のレビューの後）
数は閉じた問題なのでコードが守る。否定・取り消し・言い直し・断りは意味の問題で、語彙では閉じない（合図を足すほど誤検出も増える）。そこで役割を分ける。
- **数はコード**: 候補の列挙・参照を値に戻す・使われない数・料金表と合計の照合（条件 1〜4・6〜16）。
- **意味はモデル**: 行ごとに `status`（`done` やった／`negated` 否定・取り消し・断り／`corrected` 言い直し／`unsure` 確かでない）と根拠の候補 ID（言い直しは訂正前・訂正後の数の候補 ID）を返す。`done` 以外は必ず確認事項（条件 17）。別に、否定・取り消し・断りに当たる文を発話番号とその文で列挙させ、その文に入る候補を使った行も確認事項にする（条件 18。行の判定と文の判定が食い違えば聞き返す、二重の網）。作業でないと判断した発話は行にしない（今のまま）。
- **語彙の合図はコード**（条件 5）: 三つ目の網として残す。誤検出は承知の上。「なし」「しね」の誤検出は実録音で数えてから外すか決める。
- 発話をまたぐ訂正: モデルの `corrected` と、コードの条件 19 で拾う。
- **最後は父の承認**: モデルも語彙も否定と気づかない言い方は通る。父の目が守り（下の「割り切るもの」）。

Codex の 2 回目のレビューで確定した欠陥（どれも V3 の時点で確認事項にならない。例は架空）:
1. 語彙に無い否定が通る: 「脱着4本は替えてない。」「バランスはしません。」「バルブは替えね。」「バランスは大丈夫です。」「バランスはいいです。」を行にしても、否定の合図に当たらない。
2. 発話をまたぐ訂正が通る: 「脱着4本。」「いや2本。」「バランスも。」で、脱着に 4本、バランスに 2本 を付けると、使われない数が無く、どの条件にも当たらない。
うるさい例（合図に当たるが否定ではない）: 「脱着しないとだめだ。」（しない）、「バランスも替えたしね。」（しね）、「傷は問題なし、脱着4本。」（なし）。

## 確認事項になる条件
1. 数量の参照が無い。1 つずつ数える単位（本・個・台・輪・枚・つ・箇所・回）の数量が整数でない（「0.4本」。セット・式などは見ない）
2. 言われた単価・金額がどの行にも使われていない（距離によらない）
3. 言われた数量・単位の付かない数が使われず、いずれかの行が参照する発話から 20 秒以内にある（言い直し。前後の発話をまたいでよい。単位は問わない）。使われた数が別の行に付いた言い直しは条件 19
4. 円があるのに読めない箇所、読めない数の並びがある（STT の崩れ。距離によらない。小数点の片側が欠けた「.4本」を含む）
5. 行が参照する候補（品目・数量・単価・金額）のどれかの文か、同じ品目（正式名）の別の語の文に否定の合図がある（「脱着4本。脱着はいらない。」）（文は「。！？」と発話の終わりで区切り、「、」では切らない。合図は しない・いらない・不要・なし・まいね・わがね… を `resolve.ts` の 1 か所に置く）。三つ目の網で、誤検出（「しないとだめだ」「替えたしね」「問題なし」）は承知の上。語彙では閉じないので、合図を足して否定を拾い切ろうとしない（条件 17・18 が主）
6. 2 行が同じ語や同じ候補を共有する
7. 1 行の根拠が 20 秒に収まらない（時刻は発話から計算）
8. 品目の語が指した発話に無い
9. 料金表に無い／別名があいまい
10. 発話の単価 ≠ 料金表
11. 単位が料金表と違う
12. 同じ料金表品目の行が 2 つ
13. 数量 × 単価 ≠ 言った金額
14. 言った合計 ≠ 計算した合計（行の確認事項があれば照らさない。税込みの合計は税率が決まるまで必ず確認事項で、一緒に言った税抜きの合計は照らす）。確認事項の欄は `total`
15. 料金表の語が出たのに行になっていない（質問が増えるなら外す）。否定の合図の文の語と、モデルが挙げた否定の文（条件 18 と同じく文全体に広げる）の語は除く
16. 数量の単位と、単価の「1＋単位」の単位が違う（「ゴムバルブ4本、1セット330円」）
17. モデルが行の `status` を `done` 以外（否定・言い直し・確かでない）にした。`status` によらず `correctedFrom`・`correctedTo` のどちらかを書いた（モデルが言い直しに気づいて書いたものは必ず確かめる）。`correctedFrom`・`correctedTo` は数の候補（qty・bareNumber・unitPrice・amount）だけを指せる（スキーマの enum と `resolve.ts` の両方で見る。違えば「参照が不正」）
18. モデルが否定・取り消し・断りの文とした文は、必ずどこかの確認事項にする。挙げた文は指した発話の中の一致を全部探し、それぞれを文全体（条件 5 と同じ区切り）に広げて見る（一部だけ写した「替えてない」も、同じ文が 2 回ある 2 回目も拾う）。(1) その文に、行が使った候補（品目・数）か、同じ品目（正式名、料金表に無い品目は語そのもの）の語が入る行があれば、その行の確認事項（「脱着4本。」「脱着はやってない。」）。(2) 文に品目の語があり、同じ品目の行が無ければ確認事項にしない（モデルが正しく行を作らなかった。条件 15 の除外と同じ）。(3) 文に品目の語が無ければ（「やっぱりやめます。」「バルブは大丈夫です。」で「バルブ」が料金表の語でない場合）、文の発話から 20 秒以内に evidence か参照の候補がある `negated` の行のうち最も近い行の確認事項（その行は既に確認事項なので守りは減らない）。そのような行が無ければ、行に付かない確認事項。モデルが挙げた文が指した発話に無ければ、それも確認事項
19. 訂正の合図（いや・やっぱり・じゃなくて・違う）がある発話の数を使った行があり、その発話から 20 秒以内の発話の同じ単位の数量を、別の行が使っている（発話をまたぐ訂正。「脱着4本。」「いや2本。」「バランスも。」）。合図は `resolve.ts` の 1 か所に置く
20. 明細に行が 1 つも無い（0 円の請求を通さない。lineIndex -1、欄は `total`。モデルが否定の文に挙げて行を作らなかった場合も含む）

聞き返しは `questions.ts` の `toQuestions` が確認事項をまとめて作る（確認事項は減らさない）。行ごとに 1 問、行に付かない事項は理由ごとに 1 問。同じ質問の確認事項は理由の種類（否定 > 言い直し > 読めない数 > 数量 > 単価 > 単位 > 料金表 > 合計 > その他）の最上位で 1 文にする（「脱着は4本と2本のどちらですか」「ゴムバルブの4本は替えなかったのですか」「ホイールナットの単価はいくらですか」）。否定と言い直しの質問には、確認事項が指す候補の値を入れる。画面・音声への配線は V5 の残り。

使わなかった数は承認画面に灰色で出す。使わなかった数のうち質問にするのは条件 2・3・4 に当たるものだけ（行から 20 秒より遠い数量・数は灰色だけ）。

## 承認画面
行ごとに 品目・数量・単価とその出所（料金表／発話／答え）・金額・元の発話（品目・数量・単価の箇所を色分け）。下に「使わなかった数」「言った合計 = 計算 ✓」と確認事項。編集はさせず、確認事項が 0 件になるまで承認の言葉は効かない。

## 守るもの・割り切るもの
- 守る: 発話に無い数字が請求に入らない／言った金額が黙って消えない／料金表との食い違いが黙って解決されない／否定・言い直しが黙って通らない。
- 割り切る（父の目が守り。評価で件数を測る）: 同じ発話内で辻褄の合う付け違え（脱着 2 本・バランス 4 本の入れ替え）、STT が数を別の数にきれいに置き換えた場合、モデルも語彙の合図も否定・取り消しと気づかない言い方（モデルが `done` とし、否定の文にも挙げず、合図にも当たらない）。
- 脅威モデルは正直なモデルの誤り。悪意あるモデルは想定しない。

## 捨てる・残す
- `verify.ts`: ほぼ捨てる（`kanjiToNumber`・`normalizeNumbers` は `candidates.ts` へ）。
- `schema.ts`: モデルの出力を参照型に。値の付いた行はコードが作る型として残す。
- `extract.ts`: 書き直し。`build.ts`: 順を candidates → extract → resolve → price に。
- `price.ts`・`lookup.ts`: 残す。試験の Codex 18 例は参照の形に直して回帰試験として残す。

## 方言を標準語に変換する層は挟まない
1. 検証は原文との一致で成り立つ。変換すると根拠が変換後の文になり、父が自分の言葉を見られない。変換の誤りが新しい捏造の経路になる。
2. コードが読む数・単位・円は方言の影響が小さい。方言が効く品目の言い方は料金表の別名、否定・文末は合図の語彙表というデータで足りる。
3. Opus は架空の津軽弁で引用を原文のまま扱えた。新設計ではモデルの仕事がさらに軽い。
4. 方言が失われるのは STT の段で、後から変換しても戻らない。
5. 費用と遅れが増える。
語彙表をヒントとして渡すのは可（出力は原文のまま）。調査の結果は `docs/research.md`「方言と用語」。

## 決めたこと（2026-11-04 夜）
1. 言い直しは必ず聞き返す。訂正の合図があっても後の数を自動では採らない。V6 は作らない。
2. 料金表に無い品目で口で言った値段を使うかは、RacroS III を確かめてから決める（保留、#33）。
3. デモの台詞は「バルブも替えた」のまま撮る。料金表のバルブの単位は実際の料金表（#3）とデモの素材で揃え、本数だけを 1 問聞き返す。試験用の架空の料金表と文字起こしは「本」のまま変えない（単位が違えば確認事項になる規則の試験に使っているため）。
4. 否定・取り消しは、数はコード・意味はモデル・最後は父の承認で守る（上の「否定・取り消しは誰が守るか」）。語彙の合図は残すが、語彙を広げて閉じようとしない。
