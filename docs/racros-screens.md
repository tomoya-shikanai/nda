## 部品の読める度合い（UI Automation）

| 部品 | 使われ方 | 読めるか | 確度 |
|---|---|---|---|
| `NumEdit`（他社製） | 数の欄（数量・単価など） | **値が Name に出る**（数字）。Value・LegacyIAccessible の値は空 | 確 |
| `TextEdit`（他社製） | 文字の欄 | **入力した文字が Name に出る**。Value は空 | 確 |
| `ThunderRT6TextBox`（VB6 標準） | 伝票の画面の一部の欄 | Value で読める | 確 |
| `VSFlexGridL`（ComponentOne） | 明細の表 | **名前も値も空。外から中身を読めない** | 確 |
| `MSFlexGridWndClass` | 伝票の画面の別の表 | 読めない | 確 |
| `msvb_lib_toolbar` | 各画面の上のツールバー | **ボタンに名前が無い**。どのボタンかは押した位置でしか分からない（位置は画面と状態ごとに固定。伝票の画面は状態で並びが変わる） | 確 |
| `Button`（ダイアログ） | はい(Y)・いいえ(N)・OK・キャンセル・閉じる | 名前で読める | 確 |

## 画面の操作と DB の対応

- M_NOU の「保存」「印保存」を押した時刻と、`TJNL_DAT` の作成・更新の時刻（`TJNL_INSYMD`・`TJNL_UPDYMD`、yyyyMMddHHmm の文字列）が、午前の伝票すべてで分まで一致した。（確）
- 「印保存」（保存＋印刷）の伝票は印刷日の列（`TJNL_PRN_YMD1〜3`）に当日が入り、「保存」だけの伝票は入らない。種別（`TJNL_DENSYU`）によって入る列が違う。（確）どの列がどの帳票（見積書・納品書・請求書）かは未。
- `TJNL_DENSYU` は少なくとも 0〜4 があり、`TJNL_URIKBN` と組で決まっているように見える（DENSYU=1 なら URIKBN=1 が大半、2〜4 なら 0）。意味は未。
- 作った伝票を開いて「修正」→「保存」を押すと、`TJNL_UPDYMD` だけがその時刻に変わる。（確）
- DENSYU=4 の伝票で「印保存」を押しても、印刷日の列に何も入らないことがあった。（確）印刷を取り消したのか、種別で印刷しないのかは未。

## 操作の方式（#26）への意味

1. **明細を画面から読み返せない。** 明細は `VSFlexGridL` に入るので、入力後の照合は DB を読むだけの SQL（保存の後に `TJNL_DAT`・`SYAJNL_DAT` を読む）で行う。保存の時刻が分まで DB に残るので、どの伝票かを突き合わせられる。
2. **ツールバーのボタンを名前で押せない。** 保存・印保存・印刷・削除が同じ帯に並び、名前が無い。名前の許可リストが作れないので、ツールバーを自動で押す方式は危ない。座標で押す場合は、押してよい位置を画面ごとに固定し、押した後のダイアログを名前で確かめる。
3. 1 つ 1 つの欄は Name で読み返せる（NumEdit・TextEdit）。見出しの欄の照合は画面でもできる。
4. **明細はキーだけで入れられる。** 業務の記録では、明細の表の入力は Enter で次の欄へ進み、矢印・Delete で直していた。ツールバー以外にマウスを使わない道筋がある。F8 も伝票の画面で使われていた（役目は未）。
5. ツールバーを座標で押す場合は、伝票の画面の状態（新しく入れるか、作った伝票を開いたか）で同じ位置のボタンが変わる（例: 左から 5 番目が「転用」か「新規」）。押す前に状態を確かめないと、違うボタンを押す。
