## 画面の操作と DB の対応

- M_NOU の「保存」「印保存」を押した時刻と、`TJNL_DAT` の作成・更新の時刻（`TJNL_INSYMD`・`TJNL_UPDYMD`、yyyyMMddHHmm の文字列）が、午前の伝票すべてで分まで一致した。（確）
- 「印保存」（保存＋印刷）の伝票は印刷日の列（`TJNL_PRN_YMD1〜3`）に当日が入り、「保存」だけの伝票は入らない。種別（`TJNL_DENSYU`）によって入る列が違う。（確）どの列がどの帳票（見積書・納品書・請求書）かは未。
- `TJNL_DENSYU` の意味はマスタ `DENSYU_DAT` にある: 1＝納品書、2＝指示書、3＝概算見積書、4＝御見積書、5＝仮納品書。（確）0 はマスタに無い（古い伝票か、別の扱いかは未）。`TJNL_URIKBN` は納品書なら 1（売上）、見積・指示書なら 0 が大半。
- 見積書の区分のマスタ `MITKBN_DAT` は 0＝見積書、1＝注文書、2＝仮注文書。（確）伝票のどの列と結ぶかは未。
- 作った伝票を開いて「修正」→「保存」を押すと、`TJNL_UPDYMD` だけがその時刻に変わる。（確）
- 御見積書（DENSYU=4）で「印保存」を押しても、印刷日の列に何も入らないことがあった。（確）印刷を取り消したのか、見積書では入らないことがあるのかは未。

## 取込・書出し（実行ファイルの中の文字列から。画面では未確認）

- 伝票を外から入れる汎用の CSV 取込は見当たらない。（推）
- `TORI_JCR.exe` は「車販データ取込」。中古車の販売のシステム（JOCAR）から、顧客・車両・伝票を取り込む（`T_SH.CSV`・`T_KK.CSV`・`T_KS.CSV`）。（推）
- `OUT_JCR.exe` は「整備データ出力」。顧客・車両・整備の伝票と明細を CSV に書き出す（`T_KK`・`T_KS`・`T_SB`・`T_SB_DTL`）。（推）
- `TORI_EXT.exe`・`OUT_EXT.exe` は AUTOCORE 連携（原価の出力・加修データの出力）。`TORI_AD.exe` は「アウダデータ取込」。（推）
- 顧客・車両の画面（`M_CAR.exe`）に、車検証の読み取りがある。二次元コード（QR）の読み取り（「QR コードは連続で読み取れます」、登録車は左から 1〜3 個目と 4〜5 個目）と、電子車検証の IC の情報のファイル（`*.json`、署名の確かめに `rsa_public_simple_hon.xml`）の取込。コードの読み替えのマスタは `M_HEN_QR.exe`・`M_HEN_IC.exe`（`QR_HENKAN_DAT`・`IC_HENKAN_DAT`）。（推）店で使っているか、読み取りの機器があるかは未。
- → 整備の伝票を入れる道は、画面の操作だけ。車販の取込の形式に合わせて作る手は、本来の使い方でなく、確定まで入る恐れがあるので採らない。

## メニュー（RS_MENU）と顧客・車両の画面の部品（2026-11-05 夜、読むだけの巡回 `office/patrol/`）

- メニューの窓は 1 枚（`ThunderRT6FormDC`、題名「[ メニュー ] - RacroSⅢ」）。中のタイル・タブ・下のボタンは、すべて名前の無い `ThunderRT6UserControlDC`（自作の部品）で、Invoke も無い。**メニューの項目を名前で選んで開く道は無い。**（確）
- 名前と Invoke があるのは、窓の上のメニューバー（ファイル・特別処理・メンテナンス・ヘルプ・連携）と、題名の帯のボタン（最小化・最大化・閉じる）だけ。（確）
- メニューの中に `VSFlexGridL` の表が 1 つある（中身は外から読めない）。（確）
- 顧客・車両の画面（M_CAR）も同じ作り。ツールバー（`msvb_lib_toolbar`）・枠（`ThunderRT6Frame`）・自作の部品は名前が無い。名前で読めるのは題名の帯とシステムのメニューだけ。（確）
- → 画面を外から動かすなら、名前ではなく **キー操作と座標**（画面と状態ごとに固定）で行い、結果は DB で読み返すしかない。巡回は名前で許可した項目しか押さない作りなので、今夜はメニューを開いて書き出しただけで、他の画面は開いていない。前後で伝票・明細・車・排他の表の件数と最終更新の時刻が変わっていないことを SELECT で確かめた。（確）

## 操作の方式（#26）への意味

1. **明細を画面から読み返せない。** 明細は `VSFlexGridL` に入るので、入力後の照合は DB を読むだけの SQL（保存の後に `TJNL_DAT`・`SYAJNL_DAT` を読む）で行う。保存の時刻が分まで DB に残るので、どの伝票かを突き合わせられる。
2. **ツールバーのボタンを名前で押せない。** 保存・印保存・印刷・削除が同じ帯に並び、名前が無い。名前の許可リストが作れないので、ツールバーを自動で押す方式は危ない。座標で押す場合は、押してよい位置を画面ごとに固定し、押した後のダイアログを名前で確かめる。
3. 1 つ 1 つの欄は Name で読み返せる（NumEdit・TextEdit）。見出しの欄の照合は画面でもできる。
4. **明細はキーだけで入れられる。** 業務の記録では、明細の表の入力は Enter で次の欄へ進み、矢印・Delete で直していた。ツールバー以外にマウスを使わない道筋がある。F8 も伝票の画面で使われていた（役目は未）。
5. ツールバーを座標で押す場合は、伝票の画面の状態（新しく入れるか、作った伝票を開いたか）で同じ位置のボタンが変わる（例: 左から 5 番目が「転用」か「新規」）。押す前に状態を確かめないと、違うボタンを押す。
