# 試したことの記録

ベンダー・モデル・設定を試したら、1 行ずつ残す。決めたことは `docs/decisions.md`、一般の事実は `docs/research.md` に書く。

- 書式は「日付｜試したもの（ベンダー・モデル・設定）｜素材｜結果（数字）｜気づいた誤り｜費用｜次」。
- 素材は種類だけを書く（「架空の読み上げ」「父の実録音 rec-03」など）。実録音の文字起こしの全文や、客の名前・ナンバーの入った文は書かない。全文は `data/transcripts/`（リポジトリに入らない）に置く。
- 誤りは、整備の言葉の取り違えのように、個人を特定しない形で書く。

架空の音声での暫定の順位（ベンダーは決めない）: ①Scribe v2（用語の指定なし）と `gemini-3.5-transcribe` が整備の言葉・数字ともほぼ満点で並ぶ（速さは Scribe、数字の書き方は算用数字で出る transcribe） ②whisper-large-v3-turbo（廃タイヤを落とすが 0 円で 1 秒弱） ③`gemini-3.5-flash`（遅い） ④kotoba-whisper（廃タイヤ・スタッドレスを落とす）。
実録音で確かめる点: (1) 工場の騒音と父の話し方で「廃タイヤ」「組替」と金額（Scribe の「二二十円」のような崩れ）が保てるか (2) 本物の津軽弁で方言をどう書くか（say の Kyoko は「んだ」「んだんだ」を全社が「だ」「普段だ」と聞くので、架空の音声では方言を測れていない） (3) 用語の指定（Scribe `keyterms`・transcribe `custom_vocabulary`）が実録音で効くか、方言や数字を悪化させないか。
採点の注意: 漢数字は算用数字に直して比べ、「二二十」のような崩れは直さない。表記の揺れ（組み替え／組換、当たり／あたり）と方言のかな書き（まいね／マイネ）は正とした。
