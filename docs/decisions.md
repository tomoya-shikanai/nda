## 未決のこと（戦略会議の議題）

主軸の変更で、議題の前提が変わったものがある。会議で、残すか捨てるかから決める。

1. **承認の言葉**：父が選ぶ。条件は、相づちでは言わず意図して言う、「んだ」と音が離れている、父が自然に言える、客への説明にまず出ない。候補の例「よし、決まり」「これで行ぐ」「間違いねぇ」。決まったら直す所：README、`scripts/approve.ts`、`lib/son/ask.ts`、`tests/pipeline.test.ts`、`tasks/backlog.md` の T3、`docs/preregistration.md` の採点欄。
2. **整備ソフトの操作方式**：製品名と、CSV の取り込みの有無、画面部品が読めるか（pywinauto など）で決める。範囲は「入力して確認画面で止まる」まで。漢字の入力方法、二重入力の防止（案件 ID）、止めるボタンも決める。ノウハウは `.claude/skills/legacy-ops/` に貯める。
3. **README・CLAUDE.md・バックログを新しい主軸に合わせる**：T1〜T5 は旧主軸で書いた下書き。
4. **評価の設計**：旧案は 3 腕比較で、「聞くべき／聞くべきでない」「答えるべき／止まるべき」を同数そろえ、各腕 k=3 回で pass^3 を見る。新しい主軸では「請求の明細が正しいか」「分からない値で正しく止まったか」「客の待ち時間がどれだけ減ったか」に置き換えるか。
5. **息子の問いを Citations に替えるか**（旧主軸の機能。残すなら）：推奨は替える。承認済みの記録を発話単位の `search_result` で渡し、引用の無い行が 1 つでもあれば止める。structured outputs と同じリクエストでは使えない。
6. **連携の候補**：MCP サーバー（承認済みの記録だけを返す。補助扱い）、紙の控え＋原音の QR（手持ちのプリンタ）。
7. **computer use の扱い**：README の「不採用」をどうするか。事務所の PC の操作に使うかどうか。
8. **11/3 に取った証拠の扱い**：検証設計、降格の基準、入口の範囲、後検証（`lib/karte/verify.ts`）の厳しさ。
