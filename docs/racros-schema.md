# 業務ソフト（RacroS III）の DB の構造（タイヤの伝票まわり）

2026-11-04 夜に、事務所の PC の SQL Server（`.\S1DATABASE2019`）を **読むだけ** で調べた結果。接続は読むだけのログイン（db_datareader だけ）で行う（`office/racros/README.md`）。
列名・型・マスタ（工賃の台帳）と、件数の集計だけから推定した。客の情報（氏名・住所・電話・車台番号・ナンバー・備考）は見ていないし、ここにも書かない。
店の数字（件数・金額）は公開リポジトリに書かない。集計の結果は `data/private/racros/`（.gitignore）にある。

確度: **確** = 値の分布で裏づけた／**推** = 列名と分布からの推定／**未** = 分からない。

## 伝票: 見出し `TJNL_DAT` と明細 `SYAJNL_DAT`

`TJNL_DENNO`（伝票番号）で 1 対多につながる。明細の無い見出し・見出しの無い明細は無かった（確）。両方の DB に同じ形である。

| 列 | 意味 | 確度 | 取り出しでの扱い |

| `TJNL_KOKCD` | 顧客コード | 推 | 仮名 `顧客A` |
| `TJNL_CARCD` | 車両コード | 推 | 仮名 `車両001` |
| `TJNL_DENSYU`・`TJNL_TYPE`・`TJNL_URIKBN` | 伝票の種別・区分（値は 0〜5） | 未（意味は画面で確かめる） | そのまま（コード） |
| `TJNL_KDEL` | 削除の印（0 以外は削除） | 推 | そのまま。集計では 0 以外を除く |
| `TJNL_MAKER` | メーカーのコード | 推 | そのまま（コード） |
| `TJNL_SYASYU` | 車種名（半角カナ。例: ワゴンR） | 確 | 3 台以上にある値だけ残し、ほかは `<少数>` |

### 品名の扱い（`SYAJNL_NM`）

品名は工賃マスタから入るが、画面で書き換えられる。客の名前や事情が書かれ得るので、次の順で決める（`office/racros/RacrosMask.psm1` の `Protect-FreeText`）。

1. 電話番号・長い数字・メール・敬称（様・さん・殿など）・住所の語・車台番号やナンバーの形を含む → `<除外>`
2. 3 人以上の客の伝票に現れる文言（表記を NFKC でそろえて数える）→ そのまま残す
3. タイヤと読める（サイズか銘柄がある）→ `<タイヤ 銘柄 サイズ>`（読めた部分だけ）
4. それ以外 → `<自由記述>`

行の分類（履き替え・組み替え・バランスなど）は、伏せる前に PC の中で決めて列 `category` に入れる。

## タイヤの伝票の定義

明細のどれかが、上の工賃コードを持つか、品名に「タイヤ」「スタッドレス」（半角も）を含む伝票。種類は:

- `mount`: 組み替えの行があるか、タイヤ本体を売った（部品の金額が 0 より大きい）
- `swap`: それ以外で、履き替えの行がある
- `other`: パンク修理・保管・廃タイヤだけ、など

タイヤの伝票には車検・点検の行もよく一緒に載る（その他の行）。

## 明細の行の種類・税・額強制・採番（2026-11-05 夜、DB を読むだけと実行ファイルの文字列で調べた）

店の件数・割合はここに書かない（事務所の PC の中だけ）。確度: 確＝値で裏づけた／推＝推定／未＝分からない。

### 部品の行か作業の行か
- 決めるのは、その行の作業区分（`SYAJNL_SAGKBN` → `SAGKBN_DAT`）の部品区分 `SAGKBN_BYKBN`（0 部品・1 油脂・2 車両・3 材料・9 その他）と、工賃マスタの印 `KOUM_GAKU_KBN`（単価学習の有無）・`KOUM_SISU_KBN`（点数学習の有無）。部品の類か、単価学習ありなら部品の側（`SYAJNL_B_SU`・`B_TAN`・`B_KIN`）、点数学習ありなら作業の側（技術料 `SYAJNL_S_KIN`）に入る。（確: 列の名前は M_KOUM.exe の SQL の別名、行の側は件数。画面のカーソルが同じ規則で進むかは推）
- `B_KIN = B_TAN × B_SU ÷ 10`（数量は 10 倍で入る）。作業の行でも `B_SU`・`B_TAN` が入り、`S_KIN = B_TAN × B_SU ÷ 10` が成り立つ行がある。（確）
- タイヤの項目: 277 履き替え・278 組み替え・279 バランス・309 バランス測定（アルミ）は作業の行（単価学習 0・点数学習 1）。296 ゴムバルブは部品の行（単価学習 1・点数学習 0）。（確）278・279・309 には、金額が 0 で数量だけの行も多い。別の行に込みにした書き方と見られる。（推）

### 自由入力の行（項目CD 0）
- 品名 `SYAJNL_NM` はほぼ必ず入る。部品コード `SYAJNL_BUHCD` はいつも 0。品番 `SYAJNL_HINBAN` は鈑金の取替の区分の行だけ。（確）
- 取替・部品の区分の行は数量・単価・部品金額、経費・鈑金・塗装・点検の区分の行は技術料（と点数）に入る。金額がすべて 0 で品名だけの行（見出しやメモ）もある。（確／見出し・メモは推）

### 税
- **明細の金額は税抜。** 売上の消費税区分は「税抜き」（`KANRI_DAT`、M_NOU のヘルプの文字列「0:税抜き 1:税込み(明細単位)」）。（確）
- 見出しの合計 `TJNL_TOT` ＝ 区分ごとの売上 `TJNL_*_URI` の和 − 値引 `TJNL_*_NEBI` の和 ＋ 消費税 `TJNL_ZEI` ＋ 諸費用 `TJNL_SYO1〜10_KIN`。消費税は（売上 − 値引）× 率（`TJNL_ZEI_RITU`、1000＝10%）。端数は四捨五入が一番よく合う。（確）
- 明細の和と見出しの売上の和は大半で一致し、ずれは 10 円未満。ずれの出どころは未。

### 額強制
- 集計の画面で、請求する額を手で打ち直す機能（M_NOU の小窓「額強制」: 売上合計・諸費用合計・預り金・元請求額・強制金額、OK・Cancel・Reset）。元の額との差は見出しの値引 `TJNL_*_NEBI` に入る。キリのよい額に下げるのに使われている。（確）
- → 自動の入力で値引の行を明細に足す必要はない。値引は額強制か見出しの値引の欄で、人が入れる。

### 伝票種別 0
- 入金の伝票（「入金入力」M_NYUKIN で作る。明細なし、`TJNL_NYU_KIN`・`TJNL_NYU_DEN` が入る）。（確）

### 採番・削除・操作ログ
- 番号は `KANRI_DAT` が持つ（取引の番号 `KANRI_TJNL_DEN`、納品書・見積書・指示書・入金の番号）。（確）
- 削除は行ごと消え、削除の履歴の表は無い。操作ログ `LOG_DAT` に残る（`LOG_OP` 1 作成・2 修正・3 削除・5 印刷、`LOG_SYU` 1 指示書・2 見積・3 納品、`LOG_TDENNO`）。（確）
- **納品書を「修正 → 種別を御見積書に変える → 保存」すると、新しい番号の伝票ができ、元の納品書は消える**（2026-11-05 の欠番 2 つで、削除のログと作成の時刻が合った）。番号は戻らない。（確）種別を変えると番号が変わるのが仕様か、どの条件で変わるかは未（同じ日に番号が変わらなかった見積書もある）。
- → 「下書きを御見積書で保存し、後で納品書に変える」でも番号が変わり、元の伝票が消える見込みがある。自動の入力の照合は、番号でなく作成の時刻と中身で行う。

### 単位
- 明細・工賃マスタに単位の列は無い。単位マスタ `TANI_DAT`・部品マスタ `BUHIN_DAT` は 0 行（部品の在庫の機能を使っていない）。帳票の「単位」は合計の額の表記だけ。（確／帳票に単位が出ないことは推）
