## デモの核（2026-11-05 鹿内さんの決定）

父が工場で作業しながら話す → 父が事務所に戻ると、業務ソフトに請求書が確定の手前まで（下書き保存があればそこまで）できていて、それを見て喜ぶ。
- 実際の業務ソフトへの入力（#26）は必須。模擬画面（`/mock-invoice`）は控え。
- 客の照合（名前とナンバーの下 4 桁、#45）もデモに入れる。撮影は練習用の客（鹿内さん本人）と車で行う。

## 前提（決定済みのものだけ）

- 題名は「んだ (nDa) — 手は整備に、事務は相棒に。」。長さの目標は 2 分 55 秒。全編に日本語字幕。
- 起動語は「んだ クロード」。起動語の後は**合図音を待ってから**話す（起動語と続けて話すと、頭の声が録音に入らない。`device/listener/README.md`）。相棒への返事も承認も、毎回起動語から始める。
- 承認の言葉は「請求書頼む」（2026-11-04 決定、`lib/session/approval.ts`）。確認事項と客の質問が 0 件のときだけ効く。否認は「まいね」。
- 相棒の名前は「んだびょん」、声は VOICEVOX のずんだもん、話速 1.25（`lib/voice/tts.ts` の既定）。語尾の「〜なのだ」は使わない。クレジット「VOICEVOX:ずんだもん」を画面の隅と README に入れる。
- 相棒が聞き返すのは、言い換えの言葉（「タイヤ交換は、組替ですか、脱着ですか」、#46）と、言っていない本数（「バルブは何個ですか」）。最後に客（「お客様の名前とナンバーの下4桁をお願いします」）。
- **客は作業と同じ文で言わない。** ナンバーかもしれない 4 桁を含む文と、その前後の文は丸ごと伏せ字にしてから Claude に渡す作りなので（`feat/office-link`、まだ main に無い）、作業と同じ文で言うと作業の言葉も消える。客は客の質問への別の返事として言う。
- 客の照合は事務所の PC が業務ソフトの DB を読むだけで行い、両方が合う 1 組だけのとき「お客様: 〇〇 様・車種」をモニターに出す（姓と車種は画面に出すだけで、作業ファイルとログには番号だけ。`docs/design/pi-office.md` §9-1）。
- 業務ソフトは製品名を出さず「業務ソフト」と書く・言う。
- 父は税込みとは言わない（合計を言わない）。税は業務ソフトが計算する。
- ナレーションは鹿内さんか娘さん。静かな部屋で後から録り、工場の音を下に薄く敷く。
- 父の顔・店の名前・地名は動画に出してよい（鹿内さんの了承。父本人の公開の了承は撮影時にも確かめる）。リポジトリには実名・連絡先・車台番号・ナンバーを書かない。この台本でも客の姓・ナンバーは「〇〇」「〇〇〇〇」と書く。
- 数字は【 】のまま。評価を回した後に入れる（事前登録を先にコミットする。案は `docs/preregistration-draft.md`）。

## 撮影で父に頼むこと

台詞は覚えさせない。台本も見せない。普段どおり話してもらえる範囲だけを頼む。

1. タイヤ交換を普段どおりにやる。練習用の客（鹿内さん本人）の車で、ナンバーが映らない向きに置く。
2. 「んだ クロード」と言い、**合図音が鳴ってから**、やった作業を普段客に言うように言う。言い方・順番・方言は直さない。言い換え（「タイヤ交換」）や本数は言っても言わなくてもよい（言えば質問は出ない。そのときは場面 4 を「質問が出ないこともある」に差し替える）。
3. 相棒に聞かれたら、「んだ クロード」→ 合図音 → 短く答える。手は止めなくてよい。
4. 客を聞かれたら、客の姓とナンバーの下 4 桁を言う。**作業の話と同じ文に入れない**（別の返事にする）。
5. 確認事項が無くなったら「んだ クロード」→「請求書頼む」。
6. 作業が終わったら事務所に戻り、業務ソフトの画面を見る。反応は言わせない。
7. 通しで 3 回。止めずに最初から最後まで。失敗しても撮り続ける（失敗の回も素材として残す）。
8. 父の顔・店の名前・地名を映してよい（鹿内さんの了承済み）。ただし父本人の動画公開の了承を、撮影の前と撮影の時にもう一度確かめる。映したくない範囲があれば、その場で外す。

頼まないこと: 決まった文を言わせる、言い直しや否定をわざと入れてもらう、本数を言わないよう指示する（言わないのが普段なら、そのまま撮る）。

## 撮れなかった時の代わり（案 B: 再現）

撮影の日に、声 → Pi → Claude → モニター → 事務所 → 業務ソフトが繋がっていなければ案 B にする（`docs/demo-plan.md` の判断）。

- 父の声と動きは本物のまま撮る。上の頼みごとは変えない。
- モニターの状態は `/monitor?state=listening|thinking|drafting|asking|done&nav=0` を手で切り替え、父の声に合わせて同じ流れを再現する。相棒の声は前もって作った WAV を流す。
- 事務所への入力が繋がっていなければ、場面 7 は模擬画面（`/mock-invoice?play=1`）の画面録画にし、上部の帯「模擬画面（実際は業務ソフトに入力）」と字幕「実際の業務ソフトの画面ではありません」を常に出す。
- 再現の場面は右下に「再現」を常に出す。ナレーションでも 1 回「この場面は再現」と言う。捏造を構造で止める製品なので、作り物を本物に見せない。
- 父の撮影自体ができなければ、場面 3〜6 は手元と工場の音だけにし、父の台詞は字幕にしない（父が言っていない言葉を父の言葉として出さない）。

## 未決の点

1. **業務ソフトの実画面を映すか**: 2026-11-04 の決定は「実画面は映さず模擬画面」。2026-11-05 に実際の業務ソフトへの入力が必須になった。場面 7 で (a) 実画面を映す（製品名・ロゴ・他の客を映さない。他社のソフトの画面は権利の無い素材にあたるおそれ）、(b) 画面は映さず父の表情と「入っている」ことだけ、(c) 実際に入れた上で画面は模擬画面で見せる、のどれにするか。**未定**。
2. **下書き保存の有無**: 業務ソフトに下書き保存（確定・発行とは別の保存）があれば、入力は下書き保存まで。無ければ保存せず 20 分で閉じる（`docs/decisions.md` 2026-11-05、#41）。**未定**。無い場合、父が 20 分以内に事務所に戻る段取りが要る。場面 7 の最後に人が押すのが「保存」か「確定」かもこれで決まる。
