## デモの核（2026-11-05 鹿内さんの決定）

父が工場で作業しながら話す → 父が事務所に戻ると、業務ソフトに請求書が確定の手前までできていて、それを見て喜ぶ。
- 実際の業務ソフトへの入力（#26）は必須。撮影までに通らなければ下の「差し替え」。
- 客の照合（名前とナンバーの下 4 桁、#45）もデモに入れる。撮影は練習用の客（鹿内さん本人）と車で行う。
- 場面 7 は業務ソフトの本物の画面を、製品名・ロゴ・他の客を隠して映す（2026-11-08 決定）。

## 前提（決定済みのものだけ）

- 題名は「んだ (nDa) — 手は整備に、事務は相棒に。」。長さの目標は **2 分 46 秒**、上限 2 分 55 秒（3 分を超えた分は審査員が見ない）。全編に日本語字幕。
- 冒頭 18 秒で「誰の・どんな課題を・どう解決するか」を言い切る（審査基準「デモ」の 1 つ目）。
- 起動語は「んだ クロード」。起動語の後は**合図音を待ってから**話す（`device/listener/README.md`）。相棒への返事も承認も、毎回起動語から始める。
- 承認の言葉は「請求書頼む」（`lib/session/approval.ts`）。確認事項と客の質問が 0 件のときだけ効く。否認は「まいね」。
- 相棒の名前は「んだびょん」、声は VOICEVOX のずんだもん、話速 1.25。クレジット「VOICEVOX:ずんだもん」を画面の隅と README に入れる。
- 相棒が聞き返すのは、言い換えの言葉（「タイヤ交換は、組替ですか、脱着ですか」、#46）と、言っていない本数（「バルブは何個ですか」）。客は先に聞く（合図の後に父が客を言う。言わなければ「お客様の名前とナンバーの下4桁をお願いします」）。客を受けたら「作業を教えてください」（`lib/session/customer.ts`）。
- **客と作業は分けて言う。** 1 回で言っても動くが、ナンバーかもしれない 4 桁を含む文と、その前後の文は丸ごと伏せ字にしてから Claude に渡す作りなので、同じ文に入れると作業の言葉も消えて聞き返しが増える。撮影では客を先に言い、「作業を教えてください」の後に作業を言う。
- 客の照合は事務所の PC が業務ソフトの DB を読むだけで行い、両方が合う 1 組だけのとき「お客様: 〇〇 様・車種」をモニターに出す。事務所側がつながらなければ偽の事務所（`pnpm office:fake`、同じ約束事）で、字幕にそう書く。
- 業務ソフトは製品名を出さず「業務ソフト」と書く・言う。
- 父は税込みとは言わない（合計を言わない）。税は業務ソフトが計算する。
- ナレーションは鹿内さん本人（11/8 決定）。静かな部屋で後から録り、工場の音を下に薄く敷く。
- 店の言い方: 整備は父と従業員 1 人、事務は母が支える。「父が一人で回す」とは言わない（11/8 鹿内さん）。従業員と母の名前は出さない。
- ナレーションで「Raspberry Pi」と言わない（Pi が間に合わず Mac が工場役でも台本が変わらないように）。「工場の機械」と言う。
- 父の顔・店の名前（鹿内自動車）・地名（青森）は出してよい（鹿内さんの了承。父本人の公開の了承は撮影時にも確かめる）。リポジトリには実名・連絡先・車台番号・ナンバーを書かない。この台本でも客の姓・ナンバーは「〇〇」「〇〇〇〇」と書く。
- 数字の段は、測った物だけを出す。【 】や「未計測」を画面に出さない。父の実録音での評価は「これから」と言う。

## 撮影で父に頼むこと

台詞は覚えさせない。台本も見せない。普段どおり話してもらえる範囲だけを頼む。

1. タイヤ交換を普段どおりにやる。練習用の客（鹿内さん本人）の車で、ナンバーが映らない向きに置く。
2. 「んだ クロード」と言い、**合図音が鳴ってから**、やった作業を普段客に言うように言う。言い方・順番・方言は直さない。言い換え（「タイヤ交換」）や本数は言っても言わなくてもよい（言えば質問は出ない。そのときは場面 4 を「質問が出ないこともある」に差し替える）。
3. 相棒に聞かれたら、「んだ クロード」→ 合図音 → 短く答える。手は止めなくてよい。
4. 合図の後、まず客の姓とナンバーの下 4 桁を言う（練習は架空の客「仮田さん、1111」でもよい）。相棒が「作業を教えてください」と言ってから、作業を言う。**作業の話と同じ文に入れない**。
5. 確認事項が無くなったら「んだ クロード」→「請求書頼む」。
6. 作業が終わったら事務所に戻り、業務ソフトの画面を見る。反応は言わせない。
7. 通しで 3 回。止めずに最初から最後まで。失敗しても撮り続ける（失敗の回も素材として残す）。
8. 父の顔・店の名前・地名を映してよい（鹿内さんの了承済み）。ただし父本人の動画公開の了承を、撮影の前と撮影の時にもう一度確かめる。映したくない範囲があれば、その場で外す。

頼まないこと: 決まった文を言わせる、言い直しや否定をわざと入れてもらう、本数を言わないよう指示する（言わないのが普段なら、そのまま撮る）。

## 撮れなかった時の代わり（案 B: 再現）

撮影の日に、声 → 工場の機械 → Claude → モニター → 事務所が繋がっていなければ案 B にする（`docs/demo-plan.md` の判断）。

- 父の声と動きは本物のまま撮る。上の頼みごとは変えない。
- モニターの状態は `/monitor?state=listening|thinking|drafting|asking|done&nav=0` を手で切り替え、父の声に合わせて同じ流れを再現する。相棒の声は前もって作った WAV を流す。
- 事務所への入力が繋がっていなければ、場面 7 は上の「差し替え」。
- 再現の場面は右下に「再現」を常に出す。ナレーションでも 1 回「この場面は再現」と言う。捏造を構造で止める製品なので、作り物を本物に見せない。
- 父の撮影自体ができなければ、場面 3〜6 は手元と工場の音だけにし、父の台詞は字幕にしない（父が言っていない言葉を父の言葉として出さない）。

## 編集の点検

- `git log` はメールを出さない形式。端末のプロンプトにホームのパスが出ないようにする。
- 業務ソフトの画面は書き出し前にもう一度、製品名・ロゴ・他の客の有無を見る。
- 字幕は全編。書き出して長さを実測し、2:55 以下を確かめる。
- 別のアカウント（ログインしていないブラウザ）で再生できることを確かめる。
- 動画に映すのは期間中（11/2 12:30 以降）に作った物だけ。期間前の資料（`shikanai-auto`）と事務所の PC のブランチ（main に無い物）は映さない。

## 未決の点

1. **下書き保存の有無**: 業務ソフトに下書き保存（確定・発行とは別の保存）があれば、入力は下書き保存まで。無ければ保存せず 20 分で閉じる（`docs/decisions.md` 2026-11-05、#41）。#41 の調べでは、御見積書として保存した伝票を後で納品書に変えても番号は変わらない。場面 7 の最後に人が押すのが「保存」か「確定」かはこれで決まる。
2. **質問の順**: 今のコードは明細の質問を先、客の質問を最後に聞く。言い換えと本数のどちらが先かは撮ってみるまで分からない（台本は言い換えを先に書いた）。
3. **父の答えの単位**: 料金表のバルブの単位を「個」にした場合、父が「4 本」と答えると単位の違いで確認事項が増えるおそれがある。実際の料金表（#3）の単位と、答えの読み方を撮影前に確かめる。
