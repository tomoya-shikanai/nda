# 夜間バックログ

**下書き。鹿内さんと戦略を詰めて確定するまで、夜間ループを起動しない。**

形式: `- [ ] ID | コミット題名 | 受け入れ条件`。`[x]` 完了、`[!]` 要判断。状態は `scripts/night.sh` だけが更新する。
上から順に実行する。追加するのは、架空の素材で検証でき、仕様が確定したものだけ。

- [ ] T1 | feat: カルテの保存先を libSQL に移す | `lib/karte/store.ts` に保存・取得・一覧・承認更新を作る。DB は環境変数 `NDA_DB_URL`（既定 `file:data/nda.db`）で指定し、1 カルテを JSON 列で持つ。`scripts/run.ts`・`approve.ts`・`ask.ts` を移行する。後検証に不合格のカルテを承認できない規則は store 側でも守る。既存テストの主張は維持し、`file:` の一時 DB で store のテストを足す。
- [ ] T2 | feat: カルテ表示画面を作る | `/kartes` に一覧、`/kartes/[id]` に詳細を作る。詳細は症状・確かめた順・感じたこと・決めた・なぜ・作業行を表示し、列に「知識／センス／判断」のラベルを付ける。台帳に無い値は「未確認」と表示し、客の推測と父の観察を見た目で区別する。配色は生成り・墨・朱の 3 色で、朱は承認「んだ」の表示だけに使う。効果音なし、和風の装飾なし。データ取得は T1 の store を使う。データが無いときの空表示を作る。
- [ ] T3 | feat: 「んだ／まいね」の承認画面を作る | `/kartes/[id]` に承認と否認の操作を付ける。`verificationFailures` があるカルテは承認操作を無効にして理由を表示し、サーバー側でも拒否する。発火した一問と、回答の入力欄を表示する。回答は承認時だけ `answerApproved=true` になる。サーバー側の処理をテストで確かめる。
- [ ] T4 | feat: 息子の問いの画面を作る | `/ask` に問いの入力を作り、`lib/son/ask.ts` の `ask` を使う。答えられないときは「まいね。まだ父さ聞いでね」と標準語の説明を表示する。答えには確かめた順と引用を表示し、原音は `/api/audio/[recordingId]` から `#t=開始,終了` で再生する。この API は `data/audio/<recordingId>.wav` だけを返し、ID は `^[A-Za-z0-9_-]+$` に限定し、外れたら 400、無ければ 404 を返す。パス走査の拒否をテストする。API キーが無いときの画面の表示も作る。
- [ ] T5 | feat: 3 腕比較の採点表を出力する | `scripts/score-sheet.ts` を作る。案件ごとの extract／fixed／claude のカルテから Markdown 表を出力する。列は案件 ID、腕、一問、発火の有無、省略理由、父の回答、正しく答えた、正しく止まった、誤って答えた、父の回答秒数、父の確認秒数。採点の列は空欄のまま出力し、値を推定しない。出力の形をテストする。`docs/preregistration.md` は変更しない。
